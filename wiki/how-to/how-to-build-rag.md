# 如何搭建一个简单的 RAG 系统

## 适用场景

你需要构建一个基于自有文档的问答系统。
你有一批文档，例如 PDF、网页、Markdown。你希望大语言模型基于这些文档回答问题。

## 前置条件

- 具备基本的 Python 编程能力。
- 有一个大语言模型的 API 密钥。
- 有一些需要检索的文档。
- 安装了 Python 3.10 或更高版本。

## 操作步骤

### 步骤 1：准备文档

1. 将所有文档收集到一个文件夹中。
2. 支持的格式：PDF、TXT、Markdown、HTML。
3. 确保文档是文本格式，而不是图片扫描件。
4. 文档质量越高，RAG 效果越好。

### 步骤 2：安装依赖

安装以下 Python 包：

- `langchain`：RAG 框架
- `chromadb`：向量数据库
- `openai`：OpenAI API 客户端
- `pypdf`：PDF 解析

使用 pip 安装命令：
```
pip install langchain chromadb openai pypdf
```

### 步骤 3：加载和分割文档

1. 使用文档加载器读取文件。
2. 将文档分割成小块（chunk）。
3. 推荐的块大小：500-1000 个 token。
4. 块之间保留 10%-20% 的重叠，避免信息丢失。

### 步骤 4：创建向量索引

1. 初始化嵌入模型。
2. 将每个文本块转换为向量嵌入。
3. 将向量存入向量数据库。
4. 保存索引到磁盘，供后续使用。

### 步骤 5：构建检索链

1. 创建检索器，连接到向量数据库。
2. 创建大语言模型实例。
3. 设计提示词模板，包含检索到的上下文和用户问题。
4. 将检索器和模型组合成一个链。

### 步骤 6：测试和优化

1. 提出几个已知答案的问题，测试效果。
2. 检查答案是否准确，是否引用了正确的来源。
3. 根据效果调整参数：
   - 块大小
   - 检索数量
   - 提示词模板
4. 迭代优化，直到达到满意的效果。

## 常见问题

- **问：回答不准确怎么办？**
  - 检查文档质量和分割方式。
  - 增加检索的文档数量。
  - 优化提示词模板。

- **问：检索速度太慢怎么办？**
  - 使用更好的向量数据库（如 Qdrant）。
  - 减少文档总量，只保留相关内容。
  - 使用更小的嵌入模型。

- **问：如何处理长文档？**
  - 使用更细粒度的分割。
  - 使用父子块结构。
  - 使用重新排序（rerank）提升精度。
