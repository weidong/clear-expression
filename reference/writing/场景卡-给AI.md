# 场景卡 · 给 AI 的指令

> **定位**：A 档（程序性，最严）。句长 ≤ 20 字，超过 30 字报错。
> **判据与词表**以《中文技术表达规范》为准，本卡只管"怎么把话说得让 AI 不会误解"。
> **效力分级**：**应**（必须）/ **宜**（推荐）/ **可以**（可选）。

---

## 1. 为什么对 AI 要更严

| 原因 | 后果 |
|---|---|
| 它不会追问（除非你让它问） | 你少说一句，它自己补一个假设 |
| 它没有你电脑前的上下文 | "那个文件"它不知道是哪个 |
| 歧义会被放大 | 一句话两种读法，它选错的那种 |
| 它会"努力完成任务" | 你没说别做的，它可能做了 |

**核心区别**：跟人说话，对方会问；跟 AI 说话，它默认先做。所以**边界要写死**。

## 2. 五要素模板（应全部给出）

```
目标：<一句话，做什么>
输入：<文件/目录/数据在哪>
输出：<格式、放哪、叫什么>
验收：<可判定的标准>
约束：<不许做什么>
```

### 示例一：整理文件

```
目标：把 D:\04_归档 的顶层条目按 9 类归位
输入：D:\04_归档，共 51 个顶层条目
输出：一份 plan.csv，含"原路径 / 目标分类 / 把握度"三列
验收：51 行，每行都有分类，把握度低于中的单独标出
约束：不动 09 客户，不动交通银行目录，只出计划不改文件
```

### 示例二：改代码

```
目标：把 parse.ts 的解析改成流式
输入：src/parser/parse.ts，现有测试 tests/parse.test.ts
输出：改动后的文件和一句改动说明
验收：pnpm test parse 全绿，公开 API 签名不变
约束：不改依赖版本，不改测试文件，改动超过 3 个文件先停下问我
```

### 示例三：做文档

```
目标：把这份会议记录整理成一页纸纪要
输入：meeting.md（约 3000 字）
输出：decisions.md，含"决定 / 负责人 / 截止时间"三栏表
验收：每条决定都有负责人和时间，没有"待定"
约束：不补充记录里没有的内容，缺信息就标注"记录未提及"
```

## 3. 常见错误与改法

| ❌ 错误 | 问题 | ✅ 改法 |
|---|---|---|
| 帮我优化一下这个模块 | 优化什么？ | 把 parse.ts 的解析改成流式，测试全绿 |
| 整理一下这些文件 | 整理成什么样？ | 按 9 类归位，出 plan.csv，先不改文件 |
| 写得好一点 | 好是什么标准？ | 每句 ≤25 字，结论前置，给 3 个数据 |
| 顺便把格式也调一下 | "顺便"会失控 | 一次只做一件事，格式单独开一轮 |
| 你觉得怎么好就怎么来 | 等于放弃验收 | 给两个方案，说明取舍，我来选 |

## 4. 五条硬规则

### 规则 1：验收必须可判定

| ❌ 不可判定 | ✅ 可判定 |
|---|---|
| 整理干净 | 空目录数 = 0，重复文件 = 0 |
| 写得好 | 最长句 ≤ 25 字，无"可能/大概" |
| 代码质量高 | 测试全绿，圈复杂度 ≤ 10 |
| 完整 | 覆盖 6 个章节，每章 ≥ 300 字 |

**判定不了，就等于没验收。** 它会按自己的理解交付，你不满意也没法说清哪里不对。

### 规则 2：一次只给一个任务

三个任务一起给，它会把三件事搅在一起，出错你也定位不到是哪件。

**应**：拆成三轮。
**可以**：一条消息给三件事，但必须写清"按顺序做，每件做完停下等我确认"。

### 规则 3：不确定要它问，不要它猜

**应**在约束里加一句：

```
如果不确定，先问我，不要猜。
```

否则它会选一个看起来合理的假设，然后一路做到底。

### 规则 4：说清"不许做什么"

人对"别做"敏感，AI 对"要做"敏感。所以：

```
约束：
- 不修改测试文件
- 不删除任何文件
- 不装新依赖
- 改动超过 3 个文件先停下
```

### 规则 5：长任务要它报进度

```
每完成一步，告诉我：做了什么、下一步是什么、有没有偏离目标。
```

否则它跑偏了你半小时后才发现。

## 5. 让它自检（进阶）

在指令末尾加一段，能显著提升质量：

```
交付前自检，逐条回答：
1. 最长的一句多少字？超过 25 就拆。
2. 有没有"可能/大概/一些"？删掉或给数字。
3. 有没有代词指代不明？换成具体名词。
4. 同一个概念有没有换名字？
5. 验收标准逐条满足了吗？没满足的直接说，不要掩饰。
```

> 这和《中文技术表达规范》第 8 章的检查项一致，可以直接复制。

## 6. 上下文管理

| 情况 | 做法 |
|---|---|
| 一个会话做第三件事 | 停，开新会话 |
| 上下文占用接近 80% | 开新会话，把要点带过去 |
| 需要它记住前情 | 写进文件（`README.md`），不要靠对话记忆 |
| 任务跨天 | 把结论落进 `docs\`，下次读文件而不是翻记录 |

**一条经验**：让 AI 读文件，比让 AI 记住对话可靠得多。

## 7. 发布前检查（发给 AI 之前）

- [ ] 目标一句话说清了吗？
- [ ] 输入的具体路径/文件给了吗？
- [ ] 输出格式和位置定了吗？
- [ ] 验收标准可判定吗？
- [ ] 有没有写"不许做什么"？
- [ ] 有没有写"不确定先问"？
- [ ] 是不是只给了一个任务？
