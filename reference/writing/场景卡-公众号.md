# 场景卡 · 公众号文章

> **定位**：C 档（可读性优先）。判据、词表以《中文技术表达规范》为准，本卡只管"怎么写一篇读得下去的文章"。
> **版式部分改写自**《[少数派风格指南](https://manual.sspai.com/rules/manual-of-style/)》（更新于 2026-10-19），已剔除不适用条目。
> **效力分级**：采用少数派的三级——**应**（必须）/ **宜**（推荐）/ **可以**（可选）。

---

## 1. 句长与段落（数据校准）

| 项 | 标准 | 依据 |
|---|---|---|
| 句长报警线 | > 40 字 | 你语料 90 分位 = 37 字 |
| 句长错误线 | > 55 字 | 95 分位 = 55 字 |
| 段落 | 2–4 句 | 少于 2 句显得碎，多于 4 句手机上读不动 |
| 小标题 | 每 300–500 字一个 | 手机滚动阅读需要停靠点 |

**C 档不放松的**：一句一事、术语统一、数据有来源。

---

## 2. 中英混排与标点（少数派规则，全部适用）

### 2.1 空格

| 规则 | ✅ | ❌ |
|---|---|---|
| 汉字与英文、数字之间**应**加一个半角空格 | 使用 `DeepSeek` 模型 | 使用DeepSeek模型 |
| 英文与中文标点之间**不应**加空格 | 使用 DeepSeek，效果很好 | 使用 DeepSeek ，效果很好 |

> 例外：Markdown 的 `` `代码` `` 与中文之间也按此处理。

### 2.2 引号

| 场景 | 用 | 不用 |
|---|---|---|
| 中文引用 | 直角引号 `「」` | 弯引号 `“”` |
| 引号内再引用 | `『』` | — |
| 英文引用 | 弯引号 `“”` / `‘’` | 直引号 `"` `'` |
| 强调 | 不加引号 | 用引号做强调 |

> 直角引号的好处：中英混排时弯引号常套用英文字体，宽度不一致，视觉上会"塌"。

### 2.3 其他标点

| 用途 | 正确 | 常见错误 |
|---|---|---|
| 省略 | `……`（两个） | `。。。`、`...`、`…` |
| 中文破折号 | `——`（两个） | `-`、`—`、`--` |
| 范围、起止 | `–`（短横线，英文）<br>`—`（长连接号，中文） | 用减号 `-` |
| 中译人名间隔 | `·` | `•`、`●` |
| 分号 | **可以**用，但一段内不超过 1 处；能拆句就拆 | `；` 连用三四次 |

### 2.4 数字、单位、日期、货币

| 项 | 规则 | 例 |
|---|---|---|
| 数字与单位 | 之间**应**加半角空格 | `10 MB`、`3.5 GHz` |
| 日期 | `yyyy 年 M 月 d 日`，**不加前置零**，不用横线和冒号 | `2026 年 11 月 6 日` |
| 时间 | 同上 | `14 时 30 分` |
| 货币 | `数值 + 中文货币单位` | `100 美元`；不写 `$100`、`100 刀` |
| 外币 | 宜在括号内注人民币 | `100 美元（约合 720 元）` |

## 3. 用词

### 3.1 专有名词优先顺序（少数派原规则，很实用）

有多种写法时，按此顺序选：

1. **权利人自己规定的写法**（官方叫法）
2. 简体中文语境下权威或公认的写法
3. 其他合理写法

### 3.2 缩略语

缩略语第一次出现时**应**：① 括号加注全称；② 非中文缩写加注中文。

```
✅ 检索增强生成（Retrieval-Augmented Generation, RAG）
✅ 大语言模型（Large Language Model，简称 LLM）
```

### 3.3 应当避免的表达

| 类型 | 说明 | 例 |
|---|---|---|
| 未被广泛熟知的流行语、梗 | 读者看不懂，且有时效性 | "抽象"、"内卷"、"遥遥领先"（作形容时） |
| 反语、讽刺、影射 | 容易误解立场 | — |
| 靠贬低竞品衬托 | 不客观 | "相比 XX 的粗糙设计……" |
| 虚构现象作为论据 | 无证据 | "很多人都遇到过……" |
| 空泛形容词 | 无信息量 | "非常强大"、"极致体验" |

> 第二条和 STE 的"禁止隐喻、习语"是同一个道理：**修辞省掉的逻辑，要读者自己补。**

## 4. 结构与排版

| 规则 | 内容 |
|---|---|
| 标题 | **不应**跳级（h2→h4）；**不应**只为放大字体而用标题样式 |
| 段落 | **不应**用只有一句话的段落 |
| 列表 | 各项**宜**长度相近、句式相似；**不应**用它列举过短内容或代替标题 |
| 粗体 | **不应**大面积连续加粗；**不应**用粗体代替标题 |
| 斜体 | **不应**把中文设为斜体 |
| 块引用 | 内部引文不加引号；**不应**为装饰而用 |
| 行内代码 | 用于命令、文件名、路径、变量名、状态码；**不应**用于强调 |

## 5. 引用与链接

### 5.1 数据必须给来源

- **应**优先用一手来源，避免长篇全文引用
- 引用观点、数据**应**注明来源
- 引用外文整句**宜**翻译，并注明"作者自译"
- 引文很长时：文中引关键部分 + 给概述 + 给全文链接

### 5.2 链接文本

| ✅ | ❌ |
|---|---|
| 用资源本身的标题 | "点击这里" |
| 用章节名或原句 | "这篇"、"这里" |
| — | 裸链接地址 |

> 理由：链接文本是给读者判断"值不值得点"的信息，不是按钮标签。

### 5.3 图片（少数派规则里最容易被忽略的一条）

- 遮挡个人信息**应用纯色块**，**不宜**用马赛克或模糊
- **原因**：多项安全研究表明马赛克和模糊**可逆**
- 题注**不应**表达正文里没有的信息
- 用他人图片**应**标注来源

## 6. 公众号特有（少数派没有的）

| 项 | 建议 |
|---|---|
| **开头 3 行** | 决定读者留不留。先说"这篇能帮你解决什么"，别铺垫 |
| **手机屏宽** | 一段不超过手机 3 行；超过就拆 |
| **配图节奏** | 每 300–500 字一张，或每 2 个小标题一张 |
| **结尾** | 给一个具体行动（试一下 / 收藏 / 留言一个具体问题），不要"欢迎交流" |
| **标题** | 说清"给谁 + 解决什么"，不用问句和悬念 |
| **摘要** | 60 字以内，说结论不说背景 |

- [ ] 同一个东西有没有换名字？（对照术语表）
- [ ] 中英文之间加空格了吗？
- [ ] 引号用的是「」还是 ""？
- [ ] 省略号是 `……` 还是 `。。。`？
- [ ] 每个数据有来源吗？
