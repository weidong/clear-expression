第 1 篇

基础篇——为什么 STE 能让 AI 输出更有价值

了解 ASD-STE100 的起源、核心理念，以及它为什么能显著提升 AI 输出的质量。

1.1 什么是 ASD-STE100

ASD-STE100（Simplified Technical English，简化技术英语）是由欧洲航空航天和国防工业协会（ASD）制定的一套受控语言规范。它最初的目的是确保航空维修文档的清晰性和准确性，避免因语言歧义导致的安全事故。

核心规则

规则类别核心要求
词汇限制使用约 1800 个批准词汇，每个词通常只有一个含义
句子结构句子长度不超过 20 个单词，使用简单句
语态要求优先使用主动语态，避免被动语态
名词堆叠禁止 3 个以上名词堆叠（如 "system power supply unit" 需改写）
指令清晰操作步骤使用祈使句，动作明确
避免歧义禁止使用代词 "it" 指代不明，避免隐喻和习语
📌
注：本手册讨论的是 STE 的"思想"而非严格的词汇表。在中文语境下，我们借鉴其核心原则：短句子、主动语态、一词一义、结构清晰、信息密度高。

1.2 Karpathy 为什么推荐用它

Andrej Karpathy（前特斯拉 AI 总监、OpenAI 创始成员）在多次演讲和推文中提到，他使用 Simplified Technical English 的原则来约束 LLM 输出。

核心观点

  1. "LLM 输出的最大问题不是信息量不够，而是信息密度太低。"
    普通输出充斥着套话、连接词、冗余修饰。STE 风格强制每句话都承载信息。
  2. "把 LLM 当成一个有点啰嗦的初级员工，你需要给它明确的写作规范。"
    不加约束的 LLM 倾向于"凑字数"。STE 规则相当于给 LLM 一份写作质量标准。
  3. "技术文档的理想状态是：每句话都可以被执行或验证。"
    STE 风格的文档可执行性强。读者能快速找到所需信息，不需要"阅读理解"。
  4. "我让所有 AI 助手都用 STE 风格回答，效率提升了不止一倍。"
    阅读速度更快，误解率更低，信息提取更容易。

1.3 STE 提升 AI 输出质量的 5 个原理

原理 1：降低认知负荷

普通 AI 输出：长段落、复杂句、多层嵌套，读者需要反复阅读才能理解。
STE 输出：短句子、每句一个核心信息、结构分明，读者可以"扫描式阅读"。

🧠
认知科学依据：人脑工作记忆容量有限（约 4±1 个信息块），长句会快速耗尽工作记忆。

原理 2：减少歧义

普通 AI 输出：大量使用代词、模糊修饰、抽象名词。
STE 输出：明确的名词、具体的动作、可验证的描述。

🤖
AI 场景价值：当你把 AI 输出再喂给另一个 AI（Agent 链式调用）时，歧义会被指数级放大。STE 风格是 Agent 之间可靠通信的基础。

原理 3：提高信息密度

普通 AI 输出：通常 30%-50% 是"连接词、过渡语、客套话"。
STE 输出：每句话都有实质内容，信息密度可达 80% 以上。

量化对比：同样内容，STE 风格通常能节省 40%-60% 的字数。

原理 4：便于结构化提取

普通 AI 输出：格式松散，难以用程序提取关键信息。
STE 输出：结构规整，容易转换为表格、JSON、知识图谱等结构化格式。

原理 5：建立质量基线

普通 AI 输出：质量波动大，取决于模型心情和提示词技巧。
STE 输出：有明确的规则可以检查和评分，输出质量更稳定。

1.4 STE vs 普通写作：对比示例

示例 1：概念解释

普通写法
机器学习是一种人工智能的应用，它使得系统能够从经验中学习和改进，而无需进行明确的编程。机器学习的过程涉及使用数据来训练模型，通过算法来分析数据并从中学习，然后根据学习到的模式做出预测或决策。
STE 写法
机器学习是一种 AI 技术。

它让计算机从数据中学习。
不需要人工编写所有规则。

工作流程：
1. 输入训练数据
2. 算法分析数据中的模式
3. 生成模型
4. 模型对新数据做出预测

改进点：把 2 个长句拆成短句 + 列表；每句只说一件事；用编号列表展示流程；删除连接词。

示例 2：操作指南

普通写法
在进行系统配置之前，你需要确保已经备份了所有重要的数据，以防止在配置过程中可能出现的意外情况导致数据丢失。同时，建议你关闭所有正在运行的应用程序，这样可以避免配置过程中出现冲突。
STE 写法
操作前检查：
1. 备份所有重要数据
2. 关闭所有运行中的应用程序

原因：防止数据丢失和程序冲突。

改进点：使用祈使句直接给出指令；把"原因"和"操作"分开；删除套话。

1.5 STE "浓度"概念

STE 不是非黑即白的。根据场景不同，你可以调节 STE 的"浓度"。

100% STE：严格模式

适用场景：操作手册、Agent 之间消息传递、技术规范、API 文档

  • 每句不超过 15-20 字
  • 全部使用主动语态
  • 没有形容词和副词
  • 每个术语只有一个含义

80% STE：标准模式（推荐日常使用）

适用场景：日常 AI 对话、技术文档、知识卡片、工作邮件

  • 大多数句子简短（90% 在 25 字以内）
  • 偶尔使用被动语态（不超过 10%）
  • 少量必要的形容词
  • 结构清晰，有明确的层级

50% STE：轻度模式

适用场景：文章博客、产品介绍、会议纪要、面向非技术读者的解释

  • 段落不超过 4 行
  • 关键信息用短句和列表
  • 解释性内容可以适当展开
  • 保留一定的文学性和可读性

浓度选择指南

场景推荐浓度原因
Agent 系统提示词100%精确无歧义
技术操作指南100% / 80%可执行、可验证
知识库页面80%信息密度高
日常 AI 问答80%效率与可读性平衡
邮件/消息80% / 50%专业且不失礼貌
文章/报告50%兼顾可读性和信息密度
创意写作0-50%不适用严格 STE

2.1 核心 Prompt 模板

基础模板（80% 浓度）

请用 Simplified Technical English (STE) 风格回答我的问题。 要求： 1. 使用短句，每句不超过 25 个汉字 2. 每段不超过 3 句话 3. 优先使用主动语态 4. 用编号列表展示步骤或要点 5. 避免使用形容词和副词 6. 删除客套话和连接词 7. 每个术语保持一致 我的问题是： {在此处输入你的问题}

可调浓度模板

请用 STE（简化技术英语）风格回答。 STE 浓度：{100% / 80% / 50%} 浓度说明： - 100%：严格模式。每句≤15字，全主动语态，无修饰词，纯信息 - 80%：标准模式。大多数句子简短，偶尔使用被动语态，结构清晰 - 50%：轻度模式。关键信息用 STE 风格，解释性内容可适当展开 输出格式要求： - 使用 Markdown 格式 - 关键步骤用编号列表 - 概念用加粗标注 - 对比用表格 我的问题： {在此处输入你的问题}

超浓缩模式（适合快速获取信息）

请用最精简的 STE 风格回答。 要求： - 只给要点，不给解释 - 用短语，不用完整句子 - 最多 5 条 - 每条不超过 10 个字 问题：{问题}

2.3 Prompt 使用技巧

技巧 1：在系统提示词中设置默认 STE 风格

如果你使用支持自定义系统提示词的 AI 工具（如 ChatGPT 自定义指令、Claude 系统提示等），可以把 STE 要求放入系统提示词，这样每次对话都默认使用 STE 风格。

技巧 2：用"浓度滑块"动态调节

在对话中可以随时调整浓度：

  • "请用更精简的方式说" → 提高浓度
  • "请展开解释一下" → 降低浓度
  • "请用严格 STE 格式" → 切换到 100%

技巧 3：批量处理时使用统一模板

如果你需要处理大量内容（如整理知识库），先设计好固定模板，然后批量调用。这样输出格式一致，便于后续检索和使用。

3.4 三大工作流

工作流 1：摄入（Ingest）

适用场景：读书、看文章、听课程、参加会议

  1. 收集原始素材 — 保存原文，标注来源和时间
  2. 快速提取要点 — 用 AI 生成 STE 风格摘要，提取 3-7 个核心概念
  3. 创建原子卡片 — 每个概念创建一张知识卡片，添加标签和关联
  4. 归类到知识层 — 检查是否已有相关概念页，有则补充，无则新建
  5. 标记待整理 — 快速摄入的内容标记 #待整理，定期回顾

工作流 2：查询（Query）

适用场景：写东西需要资料、遇到问题找答案、复习回顾

  1. 明确查询目标 — 你要找的是概念？工具？操作步骤？
  2. 使用关键词搜索 — 先用标签过滤，再用全文搜索
  3. 从知识层入手 — 先找到概念页，从"相关"链接深入
  4. 下钻到原子层 — 需要细节时查看具体卡片
  5. 补充缺失 — 找不到内容时记录为缺口，安排补充

工作流 3：整理（Refine）

适用场景：每周/每月的知识库维护

  1. 处理 #待整理 标签 — 回顾快速摄入的内容，完善格式和关联
  2. 检查重复内容 — 搜索相似标题，合并重复的概念页
  3. 更新过时内容 — 检查工具版本，更新数据和事实
  4. 优化关联 — 添加缺失的双向链接，清理无效链接
  5. STE 质量抽检 — 随机抽取 5 个页面检查质量

4.1 为什么 Agent 需要 STE 约束

Agent 输出的 3 个典型问题

  1. 输出不稳定 — 同样的输入，输出格式差别很大；有时候啰嗦，有时候太简略
  2. Agent 之间通信不畅 — Agent A 的输出 Agent B 理解错了；信息在传递中失真
  3. 难以调试和评估 — 不知道输出质量好不好；无法量化改进效果

STE 如何解决这些问题

问题STE 解决方案
输出不稳定明确的规则 = 可预期的输出
通信失真无歧义的表达 = 信息传递准确
难以评估可检查的规则 = 可量化的质量评分
🏭
类比：没有 STE 约束的 Agent 像没有操作手册的工厂，每个工人按自己的方式干活。有 STE 约束的 Agent 像有严格 SOP 的流水线，产出稳定、可预测、可优化。

4.2 Agent 系统提示词模板

基础版系统提示词

你是一个专业的 AI 助手。请始终按照 STE（简化技术英语）规范输出。 STE 核心规则： 1. 句子简短。每句不超过 25 个汉字。 2. 每段不超过 3 句话。 3. 使用主动语态。 4. 用编号列表展示步骤和要点。 5. 删除客套话和连接词。 6. 一个术语只有一个含义，全程保持一致。 7. 避免使用代词（它、这、那），使用具体名词。 8. 重要提示单独标注。 默认浓度：80% 如果用户要求更详细，可以降到 50%。 如果用户要求更精简，可以升到 100%。 请用 STE 风格回应用户的所有问题。

进阶版系统提示词（含自检）

# 角色定义 你是一个遵循 STE 规范的专业技术助手。 # STE 输出规范 ## 语言规则 - 句子长度：≤ 25 字（中文） - 段落长度：≤ 3 句 - 语态：主动语态 ≥ 90% - 名词：具体明确，不使用模糊代词 - 术语：统一，不混用同义词 ## 格式规则 - 使用 Markdown 格式 - 步骤用编号列表 - 要点用项目符号 - 对比用表格 # 工作流程 1. 理解用户问题 2. 组织答案结构 3. 按照 STE 规则撰写 4. 执行 STE 自检 5. 如果自检不通过，重新撰写 6. 输出最终版本 + 自检评分 # STE 自检清单 回答完成后，请逐项检查： - [ ] 所有句子 ≤ 25 字 - [ ] 所有段落 ≤ 3 句 - [ ] 主动语态占比 ≥ 90% - [ ] 没有模糊的代词指代 - [ ] 没有套话和冗余修饰 - [ ] 术语使用一致 评分：___ / 10 分 如果评分低于 8 分，请改写后再输出。

4.3 STE 自检流程

自检的 5 个步骤

让 Agent 在输出答案后，自己执行以下检查：

  1. 句子长度检查 — 统计最长句子的字数，超过 25 字则拆分
  2. 段落长度检查 — 检查每段句子数量，超过 3 句则拆分
  3. 语态检查 — 统计被动语态比例，超过 10% 则改为主动语态
  4. 信息密度检查 — 删除客套话、连接词、重复信息
  5. 一致性检查 — 统一术语，检查代词指代

5.1 代码注释的 STE 规范

注释的 STE 规则

规则说明
只写"为什么"，不写"是什么"代码本身说明做了什么
单行注释 ≤ 30 字长注释拆成多行
不用模糊词要么确定，要么不写
说明前置条件和副作用这些是代码看不出来的
TODO 必须包含日期和负责人格式：TODO(名字, 日期): 内容

对比示例

差的注释
// 这个函数用来处理用户的登录请求，
// 它会先验证用户输入的信息是否有效，
// 然后查询数据库看看有没有这个用户，
// 如果有的话再验证密码是否正确...
function login(username, password) {
  // 检查用户名和密码
  if (!username || !password) {
    // 返回参数错误
    return { error: "参数错误" };
  }
}
STE 风格注释
// 用户登录验证。返回 token 或错误对象。
// 前置条件：username、password 为非空字符串
// 副作用：更新用户最后登录时间
function login(username, password) {
  // 参数校验：拒绝空值
  if (!username || !password) {
    return { error: "参数错误" };
  }
  
  // 查询用户信息（缓存优先）
  const user = db.findUser(username);
}

不同类型注释的 STE 写法

  • 文件头注释：一句话说明模块功能 + 功能列表 + 依赖列表
  • 函数注释：一句话功能说明 + 参数说明 + 返回值说明 + 规则说明
  • 复杂逻辑注释：说明为什么这么做（而非做了什么）+ 性能影响

· 系统错误
· 格式不正确

错误信息 STE 规则

6.1 文章/报告写作的 STE 应用

STE 不是让你写"干巴巴"的文字

STE 的核心是"清晰"，而不是"无趣"。对于文章和报告：核心信息用 STE 风格（确保清晰），过渡和叙事可以用普通风格（确保流畅）。推荐浓度：50% STE。

方法 1：结论先行（BLUF 原则）

BLUF = Bottom Line Up Front（结论放在最前面）。

普通结构
背景 → 分析 → 论证 → 结论
STE 结构
结论 → 理由 → 证据 → 补充说明

方法 2：信息分层法

把文章内容分为三层，每层信息密度不同：

层级内容STE 浓度读者
第一层标题 + 摘要 + 结论100%只看结论的人
第二层各节要点 + 图表80%快速浏览的人
第三层详细论证 + 案例50%需要深入了解的人

方法 3：列表化表达

能用列表说清楚的，就不用段落。适用场景：列举原因、特点、步骤；展示优缺点；总结要点。

长文写作的 STE 工作流

  1. 列大纲 — 用 STE 风格列出所有要点
  2. 填充内容 — 先不管文风，把内容写出来
  3. STE 化改写 — 按照 STE 规则精简和结构化
  4. 润色流畅度 — 加入必要的过渡
  5. 自检 — 用自检 5 步法检查

6.3 演示文稿的 STE 原则

为什么 PPT 需要 STE

PPT 的本质是"视觉化的要点展示"，不是"文档搬家"。STE 风格和 PPT 的理念高度契合：简洁、要点化、信息密度高。

STE 风格 PPT 的 5 条原则

  1. 一页一个核心信息 — 不要把多件事塞到一页，标题就是结论
  2. 文字越少越好 — 每页不超过 6 行，每行不超过 15 字，用关键词不用完整句子
  3. 用图表代替文字 — 对比用表格，流程用流程图，数据用图表
  4. 结构清晰，层层递进 — 目录页明确结构，每部分有小结页
  5. 演讲词和 PPT 分离 — PPT 只放要点，详细内容放演讲者备注

常见 PPT 结构（STE 版）

  1. 封面页 — 标题（一句话）+ 副标题 + 讲者
  2. 目录页 — 3-5 个部分，每部分 4-6 字
  3. 背景/问题（1-2 页）— 我们面临什么问题，为什么重要
  4. 方案/内容（主体，N 页）— 每节一个核心观点，每页一个要点
  5. 总结（1 页）— 3 个核心要点 + 1 个行动号召
  6. Q&A / 致谢

7.1 LLM 作为 STE 检查员

为什么用 LLM 做 STE 检查

STE 规则虽然明确，但人工检查费时费力。LLM 可以秒级完成检查，同时检查多个维度，直接给出修改建议，成本极低。

STE 检查员 Prompt

7.2 自动检查脚本

Python STE 检查器（基础版）

以下是一个简单的 Python 脚本，可以自动检测一些常见的非 STE 特征。

"""
STE 风格自动检查工具（中文）
检查内容：
1. 长句检测（>25字）
2. 长段落检测（>3句）
3. 被动语态检测
4. 套话/冗余词检测
5. 模糊代词检测
"""

import re
from typing import Dict, List, Tuple


def split_sentences(text: str) -> List[str]:
    """按中文句号、问号、感叹号拆分句子"""
    sentences = re.split(r'[。！？\n]', text)
    return [s.strip() for s in sentences if s.strip()]


def check_long_sentences(sentences, max_len=25):
    """检测长句"""
    result = []
    for i, s in enumerate(sentences):
        if len(s) > max_len:
            result.append((i + 1, s, len(s)))
    return result


# 被动语态常见模式
PASSIVE_PATTERNS = [
    r'被\w+', r'受到\w+', r'遭到\w+',
    r'得以\w+', r'由\w+所', r'为\w+所',
]

# 套话/冗余词列表
FILLER_WORDS = [
    '非常', '十分', '相当', '比较', '特别',
    '其实', '事实上', '实际上', '基本上',
    '众所周知', '不言而喻', '毫无疑问',
    '综上所述', '总而言之', '由此可见',
    '值得一提的是', '需要指出的是',
    '在某种程度上', '在一定程度上',
    '为了', '以便', '从而', '因此', '然而',
]


def ste_check(text: str) -> Dict:
    """执行完整的 STE 检查"""
    sentences = split_sentences(text)
    paragraphs = re.split(r'\n\s*\n', text)
    paragraphs = [p.strip() for p in paragraphs if p.strip()]
    
    long_sentences = check_long_sentences(sentences)
    
    # 计算分数（简化版）
    total = len(sentences)
    long_ratio = len(long_sentences) / max(total, 1)
    sentence_score = max(0, 20 - long_ratio * 40)
    
    return {
        "score": round(sentence_score + 60, 1),  # 基础分 + 句子分
        "stats": {
            "total_sentences": total,
            "total_paragraphs": len(paragraphs),
            "long_sentence_count": len(long_sentences),
        },
        "issues": {
            "long_sentences": long_sentences,
        }
    }

  • 增加术语一致性检查（需要术语表）
  • 增加名词堆叠检测
  • 增加可读性评分

浓度调节技巧

提高浓度（50% → 80%）：

  1. 删除所有形容词和副词
  2. 把段落拆成列表
  3. 被动语态改主动语态
  4. 删除连接词和过渡语
  5. 每段控制在 3 句以内

降低浓度（80% → 50%）：

  1. 加入必要的过渡句
  2. 适当展开解释
  3. 增加例子和类比
  4. 保留一些礼貌用语
  5. 段落可以稍长一些

8.4 STE 自检 5 步法

写完任何内容后，按以下 5 步检查：

步骤名称操作
第 1 步删套话 找出"非常""十分""众所周知""综上所述"等词，直接删除
第 2 步拆长句 找出超过 25 字的句子，每句拆成 2-3 个短句
第 3 步改语态 找出被动语态（"被""受到"），改为主动语态
第 4 步换代词 找出"它""这""那"，替换为具体名词
第 5 步结构优化 能用列表的不用段落，结论放最前面
