# WIKI-SCHEMA.md
# 知识库模式规范

> 本文件定义 Wiki 的结构、页面类型和工作流约定。
> LLM 在操作 Wiki 前必须阅读本文件。
> 本文件与 RULES.md、DICT.md 共同构成简明表达规范库的规范层。

---

## 一、目录结构

```
expr-wiki/
├── raw/                     # 原始来源（只读，LLM 不修改）
│   ├── articles/            # 网页文章剪藏
│   ├── papers/              # 学术论文
│   ├── books/               # 书籍章节
│   ├── notes/               # 个人笔记
│   └── images/              # 图片素材
├── wiki/                    # Wiki 页面（LLM 写入，人类阅读）
│   ├── concepts/            # 概念页面
│   ├── entities/            # 实体页面（人/组织/产品/项目）
│   ├── how-to/              # 操作指南页面
│   ├── comparisons/         # 对比分析页面
│   └── synthesis/           # 综合分析页面
├── schema/                  # 规范文件（本目录）
│   ├── RULES.md             # 简明表达规范（写作规则）
│   ├── DICT.md              # 简明词表（受控词典）
│   └── WIKI-SCHEMA.md       # 本文件
├── index.md                 # Wiki 索引（内容导向）
├── log.md                   # 操作日志（时间导向）
└── tools/                   # 工具脚本
    ├── ingest.py            # 摄入工具
    ├── query.py             # 查询工具
    └── lint.py              # 整理工具
```

---

## 二、页面类型

### 1. 概念页（concepts/）

**用途**：解释一个核心概念或术语。

**文件命名**：概念的英文名称小写，单词用连字符连接，例如 `retrieval-augmented-generation.md`。

**页面结构**：
```
---
name: 检索增强生成
name_en: Retrieval-Augmented Generation
abbreviation: RAG
category: 大语言模型 / 技术
source_count: 3
updated: 2026-09-28
---

# 检索增强生成

## 定义
[一句话定义]

## 工作原理
[编号列表或分段说明]

## 关键组成部分
[项目符号列表]

## 应用场景
[项目符号列表]

## 相关概念
- [[相关概念1]]
- [[相关概念2]]

## 来源
- [1] [来源标题](来源路径或URL)
```

### 2. 实体页（entities/）

**用途**：描述一个具体的人、组织、产品、项目等。

**文件命名**：实体名称小写，单词用连字符连接，例如 `obsidian.md`。

**页面结构**：
```
---
name: Obsidian
type: 软件
category: 工具 / 知识管理
developer: Dynalist Inc.
first_release: 2020
source_count: 2
updated: 2026-09-28
---

# Obsidian

## 描述
[一段话描述实体是什么]

## 核心特性
1. [特性1]
2. [特性2]
...

## 在本知识库中的用途
- [用途1]
- [用途2]

## 相关链接
- [[相关概念]]

## 来源
- [1] [来源标题](来源路径或URL)
```

### 3. 操作指南页（how-to/）

**用途**：分步说明如何完成一个具体任务。

**文件命名**：以 `how-to-` 开头，后面跟任务描述，例如 `how-to-setup-rag.md`。

**页面结构**：
```
---
title: 如何搭建一个 RAG 系统
category: 操作指南
difficulty: 中等
estimated_time: 2小时
updated: 2026-09-28
---

- [条件1]
- [条件2]

## 操作步骤
```

**页面结构**：

## 三、索引文件（index.md）

索引文件是 Wiki 的内容目录，按类别组织所有页面。

**格式**：
```
# 简明表达规范库 索引

## 概念（共 N 个）
- [[概念名]] — 一句话摘要 [来源数]
- [[概念名]] — 一句话摘要 [来源数]

## 实体（共 N 个）
- [[实体名]] — 一句话描述 [来源数]

## 操作指南（共 N 个）
- [[指南名]] — 说明

## 对比分析（共 N 个）
- [[对比名]] — 说明

## 综合分析（共 N 个）
- [[分析名]] — 说明
```

**更新规则**：每次摄入新内容或创建新页面后，更新索引。

---

## 四、日志文件（log.md）

日志文件记录 Wiki 的所有变更，按时间倒序排列。

**格式**：
```
# 操作日志

## [2026-09-28] ingest | 文章：RAG 技术综述
- 新增概念页：[[检索增强生成]]
- 更新概念页：[[大语言模型]]
- 新增来源 1 篇

## [2026-09-27] lint | 每周整理
- 统一术语：将"大模型"统一为"大语言模型"
- 修复 3 个页面的被动语态
- 发现 2 个待创建的概念
```

**记录类型前缀**：
- `ingest` — 摄入新来源
- `query` — 查询并生成答案（如有新页面归档）
- `lint` — 整理维护
- `update` — 手动更新规范或结构

---

## 五、工作流约定

### 摄入流程（Ingest）
1. 将新来源放入 `raw/` 对应子目录
2. 阅读来源，提取核心信息
3. 识别涉及的概念和实体
4. 检查 Wiki 中是否已有对应页面
5. 按简明表达规范创建或更新页面
6. 更新 `index.md`
7. 在 `log.md` 追加记录

### 查询流程（Query）
1. 阅读问题，确定关键词
2. 搜索 `index.md`，找到相关页面
3. 阅读相关页面内容
4. 按简明表达规范综合答案
5. 如果答案有价值，归档为新的 Wiki 页面
6. 更新索引和日志

### 整理流程（Lint）
1. 检查规范合规性（长句、被动语态、术语一致性）
2. 检查内容完整性（缺页、缺来源、数据不一致）
3. 生成整理报告
4. 执行修复（批量更新页面）
5. 更新日志
