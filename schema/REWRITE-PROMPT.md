# 一键改写指令

> 用途：让任意 AI 按简明表达规范改写一段文字，不再每次解释规则。
> 用法：把本文件第三节的指令整段复制给 AI，再附上要改写的文本或文件路径。

---

## 一、使用方式

**方式 A（推荐）**：让 AI 读取本文件，然后给出目标文件路径。

```
读取 schema/REWRITE-PROMPT.md，按其中的改写指令处理 wiki/concepts/xxx.md
```

**方式 B**：直接复制第三节的指令，粘贴到任意 AI 对话框，再附上正文。

---

## 二、改写范围

| 范围 | 是否改写 |
|---|---|
| 正文段落 | 改写 |
| 表格单元格 | 只拆长句，不动表格结构 |
| 代码块 | 不改 |
| frontmatter | 不改，只更新 `updated` |
| 引用原文（`>` 开头） | 不改 |
| 专有名词、产品名、文件名 | 不改 |

---

## 三、指令正文（复制这一段）

```text
你是一名中文技术写作编辑。请按下面的规则改写我提供的文本。

【必须遵守】
1. 一句一事。一个句子只表达一个判断。
2. 句长分档：操作步骤不超过 20 字；说明性内容不超过 25 字；科普与公众号不超过 37 字。
3. 拆句后必须补衔接词。并列用"同时、另外"；因果用"因此、原因是"；转折用"但、不过"；顺序用"先、再、最后"。
4. 一个概念只用一个词。全文统一，不混用同义表达。
5. 优先主动语态。只把"被 + 动词"改成主动；"被审对象""被……的人"这类名词和定语从句保持原样。
6. 表格单元格不超过 20 字，一格只放一个判断。需要解释时移到表下正文。
7. 不用比喻、夸张、拟人。不用"相当于""类似于"作为主要解释方式。
8. 不用生僻词和"高级词汇"来显得专业。

【绝对禁止】
- 不得删除任何事实、数字、条件、限定词。
- 不得编造来源、数字或结论。
- 不得改变原文的判断和立场。
- 不得改动代码块、frontmatter、引用块。
- 拿不准的地方保持原样，并在结果中单独列出。

【输出格式】
先输出改写后的全文。再输出一张对照表，三列：
| 原文句子 | 改写后 | 触发规则 |

最后列出"未处理项"，说明哪些地方你没改以及原因。
```

---

## 四、改完之后

1. 运行检查，确认问题数下降：

```bash
python tools/lint.py --check long-sentences
python tools/lint.py --check terms
```

2. 人工复核对照表，重点看有没有被删掉的信息。
3. 在 `log.md` 追加一条 `update` 记录。

---

## 五、常见失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 改完变啰嗦 | AI 加了过多衔接词 | 限制每段最多加一个衔接词 |
| 信息被删 | AI 把“长定语”当冗余 | 对照表逐条核对数字与条件 |
| 语气变硬 | 委婉词被换成断言 | 保留原有限定词，如“通常”“部分” |
| 专有名词被改 | AI 把产品名当普通词 | 在指令第四节的禁止项里逐个点明 |
