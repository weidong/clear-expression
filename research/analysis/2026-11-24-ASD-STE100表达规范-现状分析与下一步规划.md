### 2.3 一个重要的认知升级

Karpathy 的 LLM Wiki 让你看到了这个模式：

```
规则文件（自然语言） → AI Agent 读 → AI Agent 按规则干活 → 结果存文件 → 下次接着来
```

你已经具备了这套模式的**前四个要素**：
- ✅ 规则文件（schema.md / AGENTS.md / STE-RULES.md / STE-DICT.md）
- ✅ AI Agent（TRAE / dsh / Claude Code）
- ✅ AI Agent 按规则干活（ste-wiki 里的 Python 工具，或让 TRAE 直接读 schema）
- ✅ 结果存文件（ste-wiki 的 wiki/ 目录，或 weidong-llm-wiki 的 wiki/ 目录）

你缺的是**第五个要素**：**验证和迭代**。

Karpathy 的模式之所以能跑通，不是因为规则写得完美，而是因为它有一个**反馈循环**：
1. 写规则 → 2. AI 执行 → 3. 你看结果好不好 → 4. 改规则 → 5. 再执行 → 6. 直到满意

你现在卡在第 2 步和第 3 步之间——规则写好了，AI 也能执行，但你还没看结果好不好。

| | ste-wiki（learn-ai 下） | weidong-llm-wiki（当前项目下） |
|---|---|---|
| **什么时候建的** | 更早（有 Python 工具） | 今天刚建（TRAE 直接读 Markdown） |

| **当前状态** | 有几个 wiki 页面和工具，但长期搁置 | 刚搭好骨架 |

### 建议：合并为一套

ste-wiki 和 weidong-llm-wiki 本质上是同一件事——**让 AI 维护一套受控的知识库**。分开的问题：

1. 两套 schema 会漂移（今天改了 STE-RULES.md，忘了改 AGENTS.md）
2. 两套入口让你困惑（新资料丢哪个 raw/？）
3. 验证结果没法统一归因（是规则的问题还是工具的问题？）

### 合并方案

```

**核心变化**：

## 五、下一步做什么（7 步，按顺序）

**建议**：迁进来，集中管理。TRAE 能同时读到所有规则，不用跨目录。

### 步骤 2：修 ste-checker.py 的 6 个缺陷（2~3 小时）

《中文技术表达规范》第 9 章已经列了这 6 条，直接改：

| # | 缺陷 | 怎么改 |
|---|---|---|
| 1 | 只数汉字，英文/数字/代码记 0 | 按可见字符总数（含英文）计算句长 |
| 2 | 表格整块跳过 | 逐格检查，合并表格单元格文本 |
| 3 | **分号被当句末** | 禁用分号——遇到分号直接报 error，让拆句 |
| 4 | 被动检测误报（"由于"、"理由"） | 用更精确的正则：`被[^\s，。、；：""''（）《》！？\s]{1,5}[^\s，。、；：""''（）《》！？]` 或限定在动词前 |
| 5 | 成语/语气助词是 info 级 | 升到 warning 或 error（取决于场景档位） |
| 6 | 无主语没实现 | 加一条：每句第一个实词必须是名词或代词 |

**为什么这步先做**：因为规范已经有了，验证它好不好用的最快方式是让脚本跑一下你的 5 篇真实文章，看检出的问题你认不认。脚本修好了，才有**可量化**的验证手段。

### 步骤 3：第一次验证（3~5 小时）

选 3 篇你最近写的、你自己觉得写得不错的文章：

1. 让 ste-checker.py 跑一遍，看检出的问题
2. 让 TRAE 读了《中文技术表达规范》后，手动改写一遍
3. 对比**原版 vs 改写版**，回答：
   - 改写版的可读性真的更好了吗？
   - 改写有没有丢失原意？
   - 检出的问题里，哪些是你真的会改的？哪些是你觉得不该改的？
   - 哪些是脚本误报？

**把这 3 篇改写的结果存到 `weidong-llm-wiki/docs/validation/`**。这是你**第一次真正用起来**的证据。

### 步骤 4：精简 schema 文件（1~2 小时）

验证完之后，把确定有效的规则写进 AI 可执行的 schema 文件。

当前 schema 文件的冗余：
- STE-RULES.md（11 条规则）和《中文技术表达规范》第 3 章（句子层）有重叠
- AGENTS.md 里的"成本控制原则"和 schema.md 的三层架构有重叠
- 两个 vault 各有一套 schema

**精简目标**：

| 文件 | 定位 | 行数上限 |
|---|---|---|
| schema.md | Vault 架构 + 权限 + 安全红线 | 现有就行，不改 |
| AGENTS.md | TRAE 专用操作指令（Ingest/Query/Lint） | 80 行以内（现有已经做到了） |
| STE-RULES.md | 写作规则精简版（AI 写内容时读） | **控制在 30 条以内**，每条一句话 |
| STE-DICT.md | 受控词典（持续扩展） | 持续更新 |
| WIKI-SCHEMA.md | Wiki 页面 YAML frontmatter 格式 | 一页就行 |

**30 条 STE-RULES 的精简方向**：
- 句长阈值（三档）：3 条
- 词汇（动作词表 + 禁用词 + 术语表）：各 1 条引用（详细的放在 STE-DICT.md）
- 句子（一句一事 + 主动语态 + 指代明确 + 无主语）：4 条
- 结构（一段一主题 + 段落 ≤3 句 + 能用列表）：3 条
- 版式（空格 + 标点）：引用《写作风格指南》第三层
- **AI 改写专用规则**：5 条（"不确定时不补"、"不改变原意"、"数据缺了就标缺"等）

### 步骤 5：让 TRAE 能"一键改写"（1 小时）

把 STE-RULES.md + STE-DICT.md 作为 TRAE 的**永久上下文**，然后写一个提示词模板：

```
请按 STE-RULES.md 改写以下内容。改写要求：
1. 只改违反规则的地方，不改你觉得"可以更好"但没违反规则的地方
2. 不确定的地方，用【⚠️待确认】标注，不要自己猜
3. 改写后，列出所有改动，标注违反了哪条规则

---
以下是要改写的内容：
{{content}}
```

**怎么触发**：在 TRAE 里开这个 vault 的项目，直接粘贴原文 + 说"请按 STE 规则改写"。

### 步骤 7：建立反馈循环（长期，每周 30 分钟）

这是 Karpathy 模式真正能持续的关键：

```
每周 30 分钟：
1. 本周你写了哪些东西？
2. 用 ste-checker 跑一遍，看检出了什么
3. 你改了哪些？哪些没改？为什么？
4. 没改的那些 → 是规则太严了？还是脚本误报？
5. 改规则或改脚本，然后更新 ste-wiki
